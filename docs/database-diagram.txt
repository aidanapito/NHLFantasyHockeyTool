╔══════════════════════════════════════════════════════════════════════════════╗
║                          KEY PRINCIPLES                                       ║
╚══════════════════════════════════════════════════════════════════════════════╝

1. ⭐ Player.id is the PRIMARY KEY - Use it everywhere as foreign key
2. ⭐ PlayerIdMapping tracks ALL external IDs (NHL, ESPN, Sleeper)
3. ⭐ NEVER store external IDs directly in GameLog, FantasyRoster, etc.
4. ⭐ ONE Player entry per actual person (no duplicates)
5. ⭐ When resolving external IDs, always go through PlayerIdMapping first
